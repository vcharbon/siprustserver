# Tuning the deployment

How to change a deployment variable safely: its role, its default and unit,
the relations it keeps with other variables and the check that enforces them,
what to watch, and the trade-off either way. Where a value comes from for a
given deployment is that deployment's own sizing page; this page does not
repeat it. A product built on this stack adds its own rows in its own guide.

Every relation below is checked, but those a row marks "a derivation, not
checked": a worker or proxy refuses to start on its final configuration and
names every variable involved (`b2bua_runner_kit::ConfigCheck`, the proxy's
`ProxyConfig`), and the `siprust` chart refuses to render
(`deploy/helm/siprust/templates/checks.yaml`). A value set through a
component's `extraEnv` escapes the render checks.

## Worked example: the emergency call ceiling

`B2BUA_MAX_CALLS_EMERGENCY` is the live-call count past which every new call,
emergency included, is refused; `B2BUA_MAX_CALLS`, below it, refuses only
normal calls (ADR-0037 item 2). The pair is a protection: by default the
emergency ceiling sits a small margin above the normal one, enough for the
emergency share of the load while normal calls are refused.

- **Relations.** Emergency strictly above normal (worker start). Every peer's
  `B2BUA_REPL_BACKUP_MAX_CALLS` at least this ceiling, so every call a worker
  admits can be backed (worker start, ADR-0037 item 4). The worker's memory
  limit holds a takeover: its own calls up to this ceiling and every backup
  turned live, `limit · (1 − s) ≥ base + (C + B) · call + (N + reserve) · txn`
  (ADR-0037 item 7; checked at render by a product chart that states its
  measured costs).
- **After a worker dies.** Copies turned live are never refused; only new
  calls are. A survivor holding more live calls than its ceilings refuses new
  calls until its count falls under them. With mean holding time `T` and `L`
  calls live after the takeover, normal calls are refused for `T · ln(L / C_n)`
  and every call for `T · ln(L / C_e)`; the survivor then admits `C_n / T`
  normal calls a second.
- **Raising it** gives emergency calls priority through a takeover: set it at
  the count a survivor holds at peak, plus margin. Raise the peers' backup
  ceilings to it, the emergency RSS ceiling to what it implies, and the memory
  limit to the item 7 line with the raised `C`: a takeover can then hold
  `C + B` live calls.
- **Lowering it** toward the normal ceiling narrows the emergency band; it can
  never meet it.
- **Watch** `b2bua_new_calls_total{outcome="rejected"}` by `reason`,
  `b2bua_capacity_level`, `b2bua_active_calls`, and after a takeover
  `b2bua_repl_takeover_hydrated_total`.

## Capacity sizing (`sizing`, the `siprust` chart)

With `sizing.enabled` the chart computes the capacity values from a profile
and per-call costs (`templates/_sizing.tpl` states each formula): the
workers' `B2BUA_MAX_CALLS`, `_EMERGENCY`, `B2BUA_REPL_BACKUP_MAX_CALLS`,
`B2BUA_MAX_TXNS`, `_EMERGENCY`, the RSS ceilings and memory, and the
proxies' self-gate, branch memo and memory. A component env or self-gate
stating one of them fails the render; the computed memory replaces the
components' memory resources. Every input is required.

| value | role | relations (check) | raise / lower |
|---|---|---|---|
| `sizing.profile.cps`, `holdSeconds`, `ringSeconds` | new calls a second the cluster takes (and one proxy and one worker alone), the mean call duration ringing included, the mean ring | ring ≤ hold (render) | live calls per worker are cps × hold / workers: the worker's ceilings and memory follow them; the transaction ceiling follows cps (an empty lone worker takes it all) and the ring; the memo follows cps and the ring, never the hold |
| `sizing.profile.invitesPerCall` | INVITEs a call sends across the proxies (`PROXY_BRANCH_MEMO_INVITES_PER_CALL`) | 2..100 (schema, proxy start) | each INVITE past a basic call's two may hold a memo entry to its cap |
| `sizing.callMarginPct`, `emergencyPct`, `txnMarginPct`, `gateMarginPct` | the normal call ceiling above a worker's mean share; the emergency ceilings above the normal ones; the transaction ceiling above the larger of an empty lone worker's and a worker at its call ceiling's rate; the self-gate above cps | — | a larger `emergencyPct` admits emergency calls through a takeover and grows the memory with it (the worked example above) |
| `sizing.txnSecondsPerCall` | transaction-seconds a call holds outside its ring; a ringing call also holds its two INVITE transactions | — | measured: live transactions over the call rate, less twice the ring |
| `sizing.memory.baseBytes` | a worker's resident memory beside what its calls, backups and transactions allocate | — | measured: RSS less those allocations, at load (an idle worker's RSS understates it) |
| `sizing.memory.answeredCallBytes`, `ringingCallBytes`, `replicaBytes`, `txnBytes` | bytes allocated per answered and ringing call, per backup copy, per transaction; a call at the profile weighs the two by ring / hold | — | measured: two runs at different ringing shares solve the call pair |
| `sizing.memory.outboundConnections`, `connectionBytes` | the outbound connections a worker may hold open, each one's bytes, inside a full takeover's memory | a product checks its connection caps against it | — |
| `sizing.memory.slackPct` | each memory limit's slack for RSS lag and allocator retention | 0..99 (schema) | — |
| `sizing.memory.proxyBaseBytes`, `memoEntryOverheadBytes` | the proxy's resident memory beside its memo, and what an entry holds outside its accounted bytes | — | measured: fit on two proxies at different memo fills |
